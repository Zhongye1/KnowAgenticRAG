# 路由层设计

## 1. 概览

路由层是请求进入系统的第一道闸门，负责**请求处理、拦截、鉴权、限流、日志与接口定义**。核心代码：

| 内容 | 状态 | 位置 |
| --- | --- | --- |
| 路由注册（app + 插件） | ✅ | `backend/src/core/register.py`、`backend/src/plugin/router.py` |
| 中间件栈（7 层） | ✅ | `register_middleware` + `backend/src/middleware/` |
| 请求拦截（JWT/RBAC/Demo/限流） | ✅ | 中间件 + `common/security/` + `utils/limiter.py` |
| 并发限流（Redis 分布式） | ✅ | `backend/src/utils/limiter.py` |
| 统一响应与异常处理 | ✅ | `common/response/`、`common/exception/` |
| 接口定义（OpenAPI/分页/健康检查） | ✅ | `register_router`、`register_page`、`utils/openapi.py` |

## 2. 请求处理链路

```text
HTTP 请求
  → CORS                    （跨域）
  → ContextMiddleware       （注入 trace_id / request_id 到 ctx）
  → AccessMiddleware        （访问日志 + Prometheus 指标）
  → I18nMiddleware          （Accept-Language 语言切换）
  → AuthenticationMiddleware + JwtAuthMiddleware（JWT 认证，注入 request.user）
  → StateMiddleware         （IP 属地 / UA / 设备解析，写入 ctx）
  → OperaLogMiddleware      （操作日志异步队列）
  → 路由（DependsJwtAuth / RequestPermission + DependsRBAC / 业务依赖）
  → 业务 Service / DAO / 数据库
  → 统一响应 MsgSpecJSONResponse（msgspec 序列化）
  → 异常：全局 Exception Handler 兜底（含 trace_id）
```

挂载顺序见 `register_app`：`register_socket_app → register_static_file → register_middleware → register_router → register_page → register_exception`。中间件**执行顺序从下往上**（后注册先执行），与 `register.py` 注释一致。

## 3. 路由注册

### 3.1 组装流程（`register_router` + `build_final_router`）

1. `build_final_router()`（`backend/src/plugin/router.py`）：
   - `parse_plugin_config()` + `resolve_plugin_order()` 解析插件依赖顺序
   - 扩展级插件路由注入目标 app 路由（`inject_extend_router`，带 `PluginStatusChecker` 依赖）
   - 应用级插件路由注入主路由（`inject_app_router`）
2. `app.include_router(main_router)`，`DEMO_MODE` 时挂全局 `Depends(demo_site())` 拦截写操作
3. `ensure_unique_route_names`（路由名唯一校验）+ `simplify_operation_ids`（operationId = 函数名）
4. 注册健康检查 `/api/v1/health`（DB `SELECT 1` + Redis ping，异常返回 `degraded`）

### 3.2 路由分层

| 层 | 文件 | 说明 |
| --- | --- | --- |
| 主路由 | `backend/src/app/router.py` | 汇总 `admin`、`task` 的 v1 |
| 模块路由 | `app/<name>/api/router.py` | 挂载本模块 v1（前缀 `{FASTAPI_API_V1_PATH}`） |
| 分组路由 | `api/v1/<group>/` | 按业务分组（auth/sys/log/monitor…） |
| 插件路由 | `plugin/<name>/api/v1/` | 由 `plugin.toml [api.*]` 声明 prefix/tags |

### 3.3 其它挂载

- 分页：`register_page` → `add_pagination(app)`（fastapi-pagination）
- WebSocket：`register_socket_app` 挂载 `/ws/socket.io`（Socket.IO，Redis 广播 manager）
- 静态资源：`/static/upload`（上传目录）、`/static`（内置资源，`FASTAPI_STATIC_FILES`）
- 指标：`GRAFANA_METRICS_ENABLE` 时挂 `/metrics`（Prometheus ASGI）

## 4. 中间件栈

| 中间件 | 职责 | 关键实现 |
| --- | --- | --- |
| `CORSMiddleware` | 跨域 | `CORS_ALLOWED_ORIGINS`，`allow_credentials=True`（可选开启） |
| `ContextMiddleware` | 请求上下文 | `RequestIdPlugin`（`X-Request-ID`）或 `OtelTraceIdPlugin`（trace_id）写入 `ctx` |
| `AccessMiddleware` | 访问日志 + 指标 | 计时、in-progress/异常/响应计数、耗时直方图（`backend/src/middleware/access_middleware.py`） |
| `I18nMiddleware` | 国际化 | 解析 `Accept-Language`，映射 `zh-CN`/`en-US` 并写入 `i18n.current_language` |
| `AuthenticationMiddleware` | JWT 认证 | `JwtAuthMiddleware` 实现 `AuthenticationBackend`（详见 [认证授权设计](认证授权设计.md) 第 6 节） |
| `StateMiddleware` | 请求状态 | 解析 IP 属地（ip2region 离线库 + 在线兜底）、UA/OS/浏览器/设备，写入 `ctx` |
| `OperaLogMiddleware` | 操作日志 | 写操作入 `asyncio.Queue`（容量 `OPERA_LOG_QUEUE_MAXSIZE`），后台批量消费落库 |

## 5. 请求拦截

拦截按层编排，逐层收紧：

| 拦截点 | 机制 | 放行条件 |
| --- | --- | --- |
| JWT 认证 | `JwtAuthMiddleware.extract_token` → `jwt_authentication`（JWT 验签 + Redis 会话强校验） | 白名单路径（`TOKEN_REQUEST_PATH_EXCLUDE`）或无 Authorization 头 |
| 认证依赖 | `DependsJwtAuth` / `DependsSuperUser` | 路由级声明（401） |
| 授权 RBAC | `DependsRBAC`（角色菜单 / Casbin 双模式） | 超管免检、权限码命中 |
| 演示模式 | `demo_site()` 全局依赖 | `DEMO_MODE` 下仅放行 GET/OPTIONS 与白名单 |
| 限流 | `RateLimiter`（`pyrate_limiter`） | 桶内配额充足（429 + `Retry-After`） |
| 参数校验 | FastAPI/Pydantic 自动 | 不符合 schema → 422 统一响应 |
| 异常 | 全局 Exception Handler | 按异常类型映射（见第 7 节） |

> 拦截顺序要点：`RequestPermission` 必须在 `DependsRBAC` 之前声明（先设置权限码再鉴权），见 [业务模块开发规范](业务模块开发规范.md)。

## 6. 并发限流与异步

### 6.1 分布式限流（`backend/src/utils/limiter.py`）

- `RateLimiter(*rates, identifier, callback)`：声明式依赖（如 `RateLimiter(Rate(5, Duration.MINUTE))`），默认按客户端 IP 标识
- `RedisBucketFactory`：按标识符路由独立 `RedisBucket`，**本地 LRU 缓存（最多 4096 个）+ Redis 服务端时间**（`RedisTimeBucket`）保证多实例一致性
- 超限回调 `default_callback` 返回 429 + `Retry-After`；`identifier`/`callback` 均支持同步/异步
- 使用场景：登录、验证码、OAuth2 回调、生成接口等高频端点

### 6.2 异步处理

- 全链路 async：FastAPI async 路由 + SQLAlchemy 异步会话（`async_db_session`）+ 异步 Redis 客户端（`redis_client`）
- 阻塞操作隔离：Celery 探测、IP 在线查询等使用 `run_in_threadpool`，避免阻塞事件循环
- 操作日志解耦：`OperaLogMiddleware` 用 `asyncio.Queue` 异步批量落库，不阻塞响应
- 实时推送：Socket.IO（`/ws`）异步事件，任务状态、在线状态经 Redis 广播
- 后台任务：Celery worker/beat 独立进程（见 [消息队列设计](消息队列设计.md)）

## 7. 接口定义与响应规范

### 7.1 统一响应

- `ResponseModel` / `ResponseSchemaModel[T]`：`{code, msg, data}` 三要素（`backend/src/common/response/response_schema.py`）
- `response_base.success(data=...)` / `response_base.fail(res=...)` 统一出口
- 默认响应类 `MsgSpecJSONResponse`（msgspec 高性能序列化，ORM JOIN 结果友好）
- 所有响应带 `trace_id`（异常场景），便于日志关联

### 7.2 异常响应映射（`register_exception`）

| 异常 | 状态码 | 说明 |
| --- | --- | --- |
| `HTTPException` | 原码（非法码回落 400） | `dev` 返回 detail，`prod` 脱敏 |
| `RequestValidationError` / `ValidationError` | 422 | 字段级错误、i18n 文案、`dev` 附 `errors` 明细 |
| `AssertionError` | 500 | `dev` 显示断言信息 |
| `BaseExceptionError`（业务异常） | 自定义 code | `TokenError`=401、`AuthorizationError`=403、`NotFoundError`=404、`ConflictError`=409 等 |
| 未知异常 | 500 | 兜底（`Exception` handler） |

### 7.3 OpenAPI 与接口约定

- `openapi_url=/openapi`；`prod` 自动关闭（`FASTAPI_OPENAPI_URL=None`）
- `simplify_operation_ids`：operationId 取路由函数名，生成客户端方法名更友好
- `ensure_unique_route_names`：路由名重复直接启动失败
- 接口文档规范：每个端点 `summary`/`description`，schema 字段 `Field(description=...)`（见 [业务模块开发规范](业务模块开发规范.md)）
- 契约快照：`docs/api/openapi.json`、`docs/api/requests.http`

## 8. 覆盖情况结论

| 用户框定内容 | 是否已做 | 说明 |
| --- | --- | --- |
| 请求处理 | ✅ | 异步全链路 + 统一响应 + 健康检查 |
| 请求拦截 | ✅ | JWT/RBAC/Demo/限流/参数校验/异常 六层拦截 |
| 中间件 | ✅ | 7 层中间件栈 + 插件路由守卫 |
| 并发限流异步 | ✅ | Redis 分布式限流、asyncio 队列、线程池隔离、Socket.IO |
| 接口定义 | ✅ | OpenAPI/分页/操作 ID/响应契约 |

## 9. 已知缺口

- **Redis 限流桶本地缓存**：单实例最多 4096 个桶，极端多标识场景存在 LRU 淘汰重建开销
- **`BaseHTTPMiddleware` 性能**：7 层中间件中多数基于 `BaseHTTPMiddleware`，高并发下存在额外开销，压测后可按需合并（如访问日志与指标）
- **`demo_site` 为全局依赖**：对所有非 GET 请求生效，新增写接口需确认是否应纳入 `DEMO_MODE_EXCLUDE`
- **限流标识默认 IP**：`X-Real-IP` 优先，依赖网关正确透传；无网关防护时存在伪造风险
- 静态资源挂载 `/static` 仅在 `FASTAPI_STATIC_FILES` 开启；生产由 Nginx 承载（见 [构建与部署](构建与部署.md)）
