# 代码生成方案

## 1. 概览

代码生成是项目内置的开发效率工具，定位为**应用级插件**，实现「数据库表 → 通用业务代码」的自动产出。

| 内容 | 状态 | 位置 |
| --- | --- | --- |
| 插件主体 | ✅ | `backend/src/plugin/code_generator/` |
| 生成主流程 | ✅ | `service/gen_service.py` |
| 模板引擎（Jinja2） | ✅ | `utils/gen_template.py` + `templates/` |
| 类型映射 | ✅ | `utils/type_conversion.py` |
| 代码格式化 | ✅ | `utils/format_code.py`（ruff） |
| 表结构读取 | ✅ | `crud/crud_gen.py` |
| 管理 API | ✅ | `api/v1/`（business / column / gen） |

**核心思想**：**逆向工程**——从数据库元数据（MySQL `information_schema` / PostgreSQL `pg_catalog`）读取表与列信息，落库为生成配置，再用 Jinja2 模板按项目「五层架构」渲染代码，最后经 `ruff format` 输出。

## 2. 整体流程

```text
数据库表（information_schema / pg_catalog，过滤 gen_% 前缀）
  → 导入：建 gen_business（业务配置）+ gen_column（列配置，bulk_create）
  → 渲染：get_vars() 组装模板变量 → 8 类模板逐一生效
  → 格式化：.py 文件走 ruff format
  → 输出：预览（内存） / 写盘（backend/app/{app_name}）/ 下载（zip）
  → 收尾：自动注入 backend/src/app/router.py（import + include_router）
```

## 3. 两种使用模式

| 模式 | 入口 | 说明 |
| --- | --- | --- |
| 自动导表 | `POST /code-generation/generations/imports`（仅 dev） | 传 `app / table_schema / table_name`，自动生成业务 + 全部列配置 |
| 手动维护 | `/businesses`、`/columns` 的 CRUD | 手工维护业务配置与列信息后走预览/生成 |

自动导表细节（`gen_service.import_business_and_model`）：

- 表注释去掉尾部「表」字作为 `doc_comment`，类名/文件名由 `to_pascal` 推导
- 列类型取 `column_type` 大写前缀（如 `VARCHAR(64)` → `VARCHAR`），经 `sql_type_to_pydantic` 映射
- 自动跳过审计列（`id / created_time / updated_time / deleted / deleted_time`）
- 已存在同表业务则 `ConflictError`

## 4. 数据模型

| 表 | 说明 | 关键字段 |
| --- | --- | --- |
| `gen_business` | 代码生成业务配置 | `app_name / table_name / doc_comment / class_name / schema_name / filename / datetime_mixin / api_version / tag / gen_path` |
| `gen_column` | 列配置 | `name / comment / type / pd_type / default / length / is_pk / is_nullable / gen_business_id` |

> 列配置可手工调整（类型、默认值、排序），渲染以 `gen_column` 为准。

## 5. 生成产物

输出目录：`<project_root>/backend/app/{app_name}/`（`gen_path` 可覆盖），共 8 类文件 + 各层 `__init__.py`：

| 产物 | 说明 |
| --- | --- |
| `model/{filename}.py` | 继承 `Base`/`DataClassBase` + `id_key`；`datetime_mixin=True` 时含审计列 |
| `schema/{filename}.py` | `Create / Update / Delete / Get` 四件套（`SchemaBase` + `from_attributes`） |
| `crud/crud_{filename}.py` | `CRUDPlus` DAO，查询默认 `deleted=0` |
| `service/{filename}_service.py` | `get / get_list / create / update / delete` + `errors.*` |
| `api/v1/{filename}.py` | 读接口 `DependsJwtAuth`，写接口 `RequestPermission + DependsRBAC`，分页 `DependsPagination` |
| `api/router.py` | 模块路由汇总 |
| `sql/{mysql,postgresql}/init.sql` | 菜单 + 权限码 seed（含 `_snowflake` 变体） |
| `__init__.py` | 各层聚合导出（`model/__init__.py` 自动带模型 import） |

`api/router.py` 生成后，`_inject_app_router` 会自动向 `backend/src/app/router.py` 追加：

```python
from backend.src.app.{app_name}.api.router import v1 as {app_name}_v1
router.include_router({app_name}_v1)
```

## 6. 模板引擎

- Jinja2 `Environment`：`FileSystemLoader` + 异步渲染（`render_async`），`sqlalchemy_type` 过滤器注入
- `get_template_path_mapping`：模板路径 → 生成路径映射（Python 6 类 + SQL 2 类）
- `get_vars`：`app_name / class_name / table_name / permission / models / database_type / now` 等；`DATABASE_PK_MODE=snowflake` 时额外生成菜单与按钮雪花 ID
- 模板按需导入（如 `TEXT` 才引 `UniversalText`、`TIMESTAMP` 才引 `TimeZone`、按方言引 `sqlalchemy.dialects.mysql/postgresql`），避免无用 import

### 6.1 模型类型智能映射（`model.jinja`）

| 列类型 | 生成类型 |
| --- | --- |
| `TEXT / LONGTEXT / Text` | `UniversalText`（跨库长文本） |
| `TIMESTAMP / DateTime` | `TimeZone`（时区感知） |
| `NVARCHAR / String / VARCHAR / CHARACTER VARYING` | `sa.String(length)` |
| MySQL 方言（`TINYINT / LONGTEXT / SET` 等） | `mysql.<Type>()` |
| PostgreSQL 方言（`ARRAY / INET / JSONB` 等） | `postgresql.<Type>()` |
| 其余 | `sa.<Type>()`（按 `sql_type_to_sqlalchemy_name`） |

默认值按 `pd_type` 推导：`str→''`、`int→0`、`bool→True`、`date→date.today`、`datetime→timezone.now`、容器类型 → `default_factory`。

## 7. 类型映射（`utils/type_conversion.py`）

- `GenMySQLColumnType` / `GenPostgreSQLColumnType` 两个 StrEnum：**SQL 类型 → Python 类型**（如 `BIGINT→int`、`DECIMAL→Decimal`、`JSON→dict`、`SET→list[str]`）
- 未知类型回落：SQLAlchemy `String`、Pydantic `str`
- PostgreSQL 特例归一：`CHARACTER VARYING→String`、`TIMESTAMP WITH TIME ZONE→TIMESTAMP`、`DOUBLE PRECISION→Double` 等
- 全部 `@lru_cache` 缓存

## 8. 权限码与菜单初始化

- 权限码约定：`permission = table_name.replace('_', ':')`（如 `sys_config` → `sys:config`），写接口权限为 `{permission}:add / edit / del`
- 生成的 `init.sql`（双方言）自动插入：父菜单（挂到 `System` 下）+ 4 个按钮权限记录（`add/edit/del` 等），与 [业务模块开发规范](业务模块开发规范.md) 一致
- `snowflake` 主键模式下菜单/按钮 ID 使用雪花生成，保证跨库一致

## 9. 管理 API

前缀 `/api/v1/code-generation`（`backend/src/plugin/code_generator/api/router.py`）：

| 端点 | 功能 | 权限 |
| --- | --- | --- |
| `/businesses`、`/columns` | 业务/列配置 CRUD | 读 `DependsJwtAuth`，写 `RequestPermission + DependsRBAC` |
| `/generations/tables` | 列出数据库表 | `DependsJwtAuth` |
| `/generations/imports` | 导入表（仅 dev） | `codegen:table:import` |
| `/generations/{pk}/preview` | 代码预览 | `DependsJwtAuth` |
| `/generations/{pk}/paths` | 生成路径列表 | `DependsJwtAuth` |
| `POST /generations/{pk}` | 写盘生成（仅 dev） | `codegen:local:write` |
| `GET /generations/{pk}` | 下载 zip | `DependsJwtAuth` |

## 10. 安全与限制

- **仅开发环境**：导入与写盘在非 `dev` 环境直接 `ForbiddenError`；生产只能下载 zip 手动接入
- **分布式锁**：写盘使用 `acquire_distributed_reload_lock()`，避免并发生成冲突
- **临时文件**：格式化通过 `fba_codegen_*.py` 临时文件 + `ruff format` 子进程，失败/无 ruff 时原样返回
- **不生成前端**：仅后端 Python + SQL 初始化
- **复杂度边界**：模板为通用五层 CRUD，关联关系、数据权限、复杂事务编排需生成后手工补充
- **依赖表规范**：表/列注释质量直接决定 `doc_comment`、字段 comment 与 API 摘要

## 11. 使用步骤

1. 启用 `code_generator` 插件（`sys_plugin` 启用 + 重启），确认 `gen_business` / `gen_column` 表已建
2. 开发库建好目标表（含表/列注释）
3. `POST /generations/imports` 导入（或手动维护 `/businesses`、`/columns`）
4. `GET /{pk}/preview` 预览代码，必要时调整 `gen_column`
5. `POST /generations/{pk}` 写盘（或 `GET /{pk}` 下载 zip）
6. 重启后端使新 app 路由生效；执行生成的 `init.sql` 注册菜单权限
7. 按需手工补充业务逻辑与测试
