# 业务模块开发规范

## 1. 概述

业务模块是系统功能的最小组织单元，**统一依赖数据库模型（[数据库层设计](数据库层设计.md)）与认证体系（[认证授权设计](认证授权设计.md)）**。模块按业务逐个开发，内部遵循统一的五层结构与命名约定。

模块两种形态：

| 形态 | 目录 | 说明 |
| --- | --- | --- |
| App 模块 | `backend/src/app/<name>/` | 随核心应用打包，如 `admin`（系统管理）、`task`（任务调度） |
| 插件模块 | `backend/src/plugin/<name>/` | 可插拔，如 `dict`、`config`、`notice`、`oauth2`、`code_generator`；通过 `plugin.toml` 声明 |

## 2. 模块目录结构

**App 模块**（以 `admin` 为例）：

```text
app/admin/
├── model/      # ORM 模型（__init__.py 聚合导出）
├── schema/     # Pydantic 参数/出参
├── crud/       # DAO（sqlalchemy-crud-plus）
├── service/    # 业务逻辑
├── api/        # 路由（router.py 汇总 + v1/ 分组）
├── utils/      # 模块私有工具（如 password_security）
└── tests/      # 模块测试
```

**插件模块**（以 `dict` 为例）：

```text
plugin/dict/
├── plugin.toml      # 插件元数据、路由前缀、配置
├── model/ schema/ crud/ service/ api/   # 同 App 五层
├── sql/{mysql,postgresql}/init.sql      # 菜单/权限/初始化数据（双方言）
└── hooks.py（可选）   # lifespan / setup / otel 钩子
```

## 3. 五层职责与规则

### 3.1 model —— 数据模型层

- 继承 `Base`（含审计时间 + 逻辑删除）或 `DataClassBase`（日志类等无审计字段场景）
- 主键统一 `id: Mapped[id_key] = mapped_column(init=False)`（雪花 BigInt）
- 显式 `__tablename__`；表注释放 `__table_args__`；唯一业务键用 `UniqueConstraint`（如 `uk_sys_dict_type_name_deleted`）
- 审计字段复用 Mixin（`created_by/updated_by`、`created_time/updated_time`、`deleted/deleted_time`），不自行定义
- `model/__init__.py` **必须聚合导出全部模型类**——`create_all` 与 `get_all_models` 依赖它完成注册
- 参考：`backend/src/app/admin/model/dept.py`、`backend/src/plugin/dict/model/dict_type.py`

### 3.2 schema —— 参数/出参层

- 继承 `SchemaBase`（统一序列化与枚举处理）
- 命名四件套：`CreateXxxParam` / `UpdateXxxParam` / `DeleteXxxParam`（含 `pks: list[int]`）/ `GetXxxDetail`
- 出参模型设置 `model_config = ConfigDict(from_attributes=True)`
- 每个字段必带 `Field(description=...)`，作为 OpenAPI 文档来源
- 校验规则写在 Pydantic 层（长度/正则/枚举），业务规则留在 service 层

### 3.3 crud —— DAO 层

- 继承 `CRUDPlus[Model]`（`sqlalchemy-crud-plus`），提供 `select_model` / `select_models` / `select_order` / `create_model` / `update_model_by_column` / `delete_model_by_column`
- 查询默认带 `deleted=0`（逻辑删除过滤）
- 复杂查询返回 `Select`（`get_select`），配合 `paging_data` 分页
- 模块级单例：`xxx_dao = CRUDXxx(Model)`

### 3.4 service —— 业务层

- 业务规则（查重、状态校验、关联检查）**必须放在 service**，不允许散落在 api
- 异常统一抛 `errors.*`（`NotFoundError` / `ConflictError` / `RequestError` / `AuthorizationError`），不自行拼响应
- 写操作依赖事务会话；`get_list` 用 `paging_data(db, select)`
- 类方法建议 `@staticmethod` + 模块级单例 `xxx_service = XxxService()`

### 3.5 api —— 接口层

- 路由依赖按固定顺序声明：`Depends(RequestPermission('perm'))` **必须放在** `DependsRBAC` 之前（先声明权限码再鉴权）
- 会话注入：读 `CurrentSession`，写/事务 `CurrentSessionTransaction`
- 响应：`response_base.success(data=...)` / `response_base.fail()`，类型 `ResponseModel` / `ResponseSchemaModel[...]`
- 分页：`DependsPagination` 依赖 + `ResponseSchemaModel[PageData[GetXxxDetail]]`
- 高频端点加 `RateLimiter`（如登录、OAuth2 回调）
- 路由汇总到 `api/router.py`：`v1.include_router(module_router, prefix=..., tags=...)`

## 4. 认证授权接入规则

| 接口类型 | 依赖组合 | 说明 |
| --- | --- | --- |
| 查询/列表 | `DependsJwtAuth` | 登录即可 |
| 写操作 | `Depends(RequestPermission('mod:entity:action'))` + `DependsRBAC` | 权限码 + 角色菜单鉴权 |
| 超管专属 | `DependsSuperUser` | 仅超级管理员 |
| 数据范围 | `filter_data_permission()` | 按角色数据规则过滤（超管不过滤） |

- **权限码规范**：`{模块}:{实体}:{动作}`，动作使用 `add / edit / del / exec / revoke`（如 `sys:user:del`、`sys:task:exec`、`dict:type:add`）
- 权限码必须与 `sys_menu.perms` 中的记录一致（见第 6 节初始化数据）
- 新增写接口时必须同步在初始化 SQL 中登记菜单权限，否则 RBAC 校验不通过

## 5. 数据库接入规则

- 模型自动注册：`get_all_models()`（`backend/src/utils/dynamic_import.py`）扫描 `app/*/model` 与插件 `model` 包——只要 `__init__.py` 聚合导出即可
- 建表：未上线阶段由 lifespan `create_all` 负责（迁移为占位，见 [数据库层设计](数据库层设计.md) 第 4 节）
- 初始化数据：插件在 `sql/{mysql,postgresql}/init.sql` 提供（菜单 + 字典 + 业务种子数据），`destroy.sql` 提供卸载
- 新增字段/表在未上线阶段直接改模型即可；上线后需走 Alembic 基线（当前占位）

## 6. 插件模块特殊规则

`plugin.toml` 关键段：

| 段 | 用途 |
| --- | --- |
| `[plugin]` | 元数据：summary/version/tags/database 支持方言 |
| `[app]` | `extend = "admin"` 将插件路由注入扩展目标 app；`router = ["v1"]` |
| `[api.<module>]` | 声明 `prefix` 与 `tags`，插件路由自动挂载 |
| `[settings]` | 插件配置项默认值（并入全局 `Settings`） |

- 插件模型注册走 `get_plugin_models()`（`backend/src/plugin/core.py`），同样依赖 `model/__init__.py` 导出
- 插件可注册 `hooks.py`：`lifespan`（plugin 阶段）、`setup`、`otel`，见 `backend/src/plugin/hooks.py`
- 依赖插件用 `depends_on` 声明；必需插件由 `PLUGIN_REQUIRED` / `RBAC_ROLE_MENU_MODE` 决定（casbin_rbac）
- 参考完整插件：`backend/src/plugin/dict/`（模型 + CRUD + SQL 初始化全套）

## 7. 新模块开发 Checklist

- [ ] 按模板建目录：`model/ schema/ crud/ service/ api/v1/`（插件含 `plugin.toml`、`sql/`）
- [ ] 定义模型并**在 `model/__init__.py` 导出**，启动验证表已创建
- [ ] 编写 `Create/Update/Delete/Get` 四件套 schema（含 description）
- [ ] CRUD DAO（`deleted=0` 过滤、`get_select` 支持分页）
- [ ] service 业务规则 + `errors.*` 异常
- [ ] api 路由：读接口 `DependsJwtAuth`，写接口 `RequestPermission + DependsRBAC`
- [ ] 在 `api/router.py` 挂载路由
- [ ] `init.sql`（双方言）登记菜单与权限码，运行验证 RBAC 生效
- [ ] 补充模块测试（参考 `backend/src/app/admin/tests/`）与 `docs/api/requests.http` 接口示例
- [ ] 检查 `task env:check` / 启动无告警，跑一次接口冒烟
