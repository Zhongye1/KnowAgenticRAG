# 认证授权设计（安全网关）

## 1. 概览

认证授权是系统的安全网关，覆盖「你是谁（认证）→ 你能做什么（授权）→ 你能看哪些数据（数据权限）」三段链路。核心代码：

| 内容 | 状态 | 位置 |
| --- | --- | --- |
| 认证体系（登录/登出/刷新/会话） | ✅ 已实现 | `backend/src/app/admin/service/auth_service.py`、`api/v1/auth/auth.py` |
| 密码哈希（bcrypt） | ✅ 已实现 | `backend/src/app/admin/utils/password_security.py` |
| JWT 生成与校验 | ✅ 已实现 | `backend/src/common/security/jwt.py` |
| Bearer 认证依赖 | ✅ 已实现（`HTTPBearer` + `DependsJwtAuth`） | `backend/src/common/security/jwt.py` |
| 认证中间件 | ✅ 已实现 | `backend/src/middleware/jwt_auth_middleware.py` |
| 权限注入（RBAC/数据权限） | ✅ 已实现 | `backend/src/common/security/rbac.py`、`permission.py` |
| OAuth2 第三方登录 | ✅ 已实现（插件） | `backend/src/plugin/oauth2/` |

**技术选型**：

- 密码哈希：`pwdlib` + `BcryptHasher`（bcrypt，自动加盐）
- JWT：`python-jose`，HS256，access（1 天）+ refresh（7 天）双令牌
- 会话状态：**Redis 服务端会话**（token 明文存 Redis，可即时撤销/单端登录踢下线）
- Bearer 依赖：**未使用 FastAPI 的 `OAuth2PasswordBearer`**，改用 `HTTPBearer` + 自定义 JWT 中间件（见第 5 节说明）
- 第三方登录：OAuth2 插件（GitHub / Google），与自建账号体系通过 `sys_user_social` 绑定

## 2. 认证体系

### 2.1 认证链路（请求处理顺序）

```text
HTTP 请求
  → JwtAuthMiddleware.extract_token()        # 提取 Authorization: Bearer <token>（白名单跳过）
  → jwt_authentication()                      # 解密 JWT + Redis 会话比对 + 用户缓存
  → request.user / request.auth.scopes       # Starlette 认证态注入
  → DependsJwtAuth / DependsRBAC             # 路由级依赖二次校验
  → 业务接口（CurrentSessionTransaction 注入事务会话）
```

### 2.2 登录流程

`POST /api/v1/auth/login`（`auth_service.login`）：

1. `load_login_config(db)`：从 `sys_config` 动态加载登录配置（验证码开关等）
2. 验证码校验（`LOGIN_CAPTCHA_ENABLED` 时）：Redis 比对 `fba:login:captcha:{uuid}`
3. `user_verify()`：查用户 → 状态/锁定检查 → `password_verify()` 校验密码
4. 失败处理：`handle_login_failure` 累计失败次数，达到 `USER_LOCK_THRESHOLD`（默认 5 次）锁定 `USER_LOCK_SECONDS`（5 分钟）
5. 成功处理：清空锁定计数 → `create_access_token` + `create_refresh_token`
6. refresh token 写入 **HttpOnly Cookie**（`fba_refresh_token`），access token 返回响应体
7. 后台任务记录登录日志（`sys_login_log`）

### 2.3 会话管理（Redis）

| 场景 | 行为 |
| --- | --- |
| 多端登录 | `multi_login=True`：每端独立 `session_uuid` 并存 |
| 单端登录 | `multi_login=False`：登录前删除该用户全部旧 token（踢下线） |
| 刷新 | `create_new_token` 校验 Redis 中的 refresh token 后轮换，旧 access/refresh 一并删除 |
| 登出 | `logout` 删除 Redis 中的 access/refresh/extra info，并清 Cookie |
| 会话即撤 | 任意时刻删 Redis key 即失效，无需等 JWT 过期 |

## 3. 密码哈希

`backend/src/app/admin/utils/password_security.py`：

```python
password_hash = PasswordHash((BcryptHasher(),))

get_hash_password(password, salt)   # bcrypt 加盐哈希
password_verify(plain, hashed)      # 校验
```

- 哈希库：`pwdlib`（Passlib 后继者），hasher 为 bcrypt，密码存储为 `$2b$` 格式（自动盐）
- **明文密码只出现在登录/改密请求体**，任何地方不落库、不打印

密码安全策略（`validate_new_password` + `password_security_service`，均可通过 `sys_config` 动态调整）：

| 策略 | 默认 | 说明 |
| --- | --- | --- |
| 最小/最大长度 | 6 / 32 | `USER_PASSWORD_MIN/MAX_LENGTH` |
| 复杂度 | 数字 + 字母 | 特殊字符可选（`USER_PASSWORD_REQUIRE_SPECIAL_CHAR`） |
| 历史去重 | 最近 3 次 | `USER_PASSWORD_HISTORY_CHECK_COUNT`，复用即拒绝 |
| 有效期 | 365 天 | `USER_PASSWORD_EXPIRY_DAYS`，0 表示永不过期 |
| 到期提醒 | 7 天 | `USER_PASSWORD_REMINDER_DAYS`，登录响应返回剩余天数 |
| 失败锁定 | 5 次 / 5 分钟 | `USER_LOCK_THRESHOLD` / `USER_LOCK_SECONDS`，0 禁用 |

## 4. JWT 生成与校验

`backend/src/common/security/jwt.py`：

### 4.1 生成（access / refresh）

```python
jwt_encode(payload)                         # HS256 签名
create_access_token(user_id, multi_login)   # 载荷: session_uuid / exp / sub；写入 Redis
create_refresh_token(session_uuid, user_id) # 仅用于换取新 access
create_new_token(refresh_token, ...)        # 刷新：校验 Redis 后轮换双令牌
revoke_token(user_id, session_uuid)         # 撤销
```

- **载荷最小化**：JWT 内只放 `session_uuid`、`exp`、`sub(user_id)`，不携带角色/权限等易失效信息
- 用户详情走 Redis 缓存（`fba:user:{user_id}`，`get_jwt_user`），失效自动回源数据库
- 附加信息（登录 IP/OS/浏览器等）独立存储 `fba:token_extra_info:{user_id}:{session_uuid}`

### 4.2 校验

```python
jwt_decode(token)   # 验签 + 校验 exp + 必需字段；异常统一抛 TokenError(401)
jwt_authentication(token)   # 解密 → 比对 Redis 会话 → 加载用户 → 注入 ctx
```

- 过期/无效：`TokenError`（401 + `WWW-Authenticate: Bearer`）
- **Redis 会话比对是强校验**：即使 JWT 签名合法，Redis 中不存在或与存储不一致仍拒绝（防重放/登出后复用）

### 4.3 令牌参数

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `TOKEN_SECRET_KEY` | 必填 | `secrets.token_urlsafe(32)`；**部署必须更换** |
| `TOKEN_ALGORITHM` | `HS256` | 签名算法 |
| `TOKEN_EXPIRE_SECONDS` | 86400（1 天） | access token 有效期 |
| `TOKEN_REFRESH_EXPIRE_SECONDS` | 604800（7 天） | refresh token 有效期 |
| `TOKEN_REDIS_PREFIX` 等 | `fba:*` | Redis 会话键前缀 |

## 5. Bearer 依赖与依赖注入

### 5.1 为什么不用 `OAuth2PasswordBearer`

- FastAPI 内置 `OAuth2PasswordBearer` 面向「OAuth2 密码模式 + Swagger 授权按钮」，仅做**无状态 JWT 验签**，无法配合本项目「Redis 服务端会话」做强校验
- 本项目使用 `HTTPBearer` + `jwt_authentication_verify`，认证发生在**中间件层**（`AuthenticationMiddleware` + `JwtAuthMiddleware`），路由级依赖只做收口与授权

### 5.2 认证依赖

`backend/src/common/security/jwt.py`：

```python
def jwt_authentication_verify(request, token: Annotated[HTTPAuthorizationCredentials, Depends(HTTPBearer())]) -> str:
    if isinstance(request.user, UnauthenticatedUser):
        raise errors.TokenError
    return token.credentials

DependsJwtAuth = Depends(jwt_authentication_verify)      # 登录即可访问
DependsSuperUser = Depends(superuser_verify)             # 仅超管
```

接口使用示例（`backend/src/app/admin/api/v1/auth/auth.py`）：

```python
@router.get('/codes', dependencies=[DependsJwtAuth])
async def get_codes(db: CurrentSession, request: Request) -> ...:
```

### 5.3 授权依赖

`backend/src/common/security/rbac.py`：

```python
DependsRBAC = Depends(rbac_verify)
```

校验顺序（白名单 → JWT 状态 → 超管免检 → 角色启用 → 菜单分配 → 后台操作 → 权限码 / Casbin）：

1. `TOKEN_REQUEST_PATH_EXCLUDE` / `_PATTERN` 白名单跳过
2. `request.auth.scopes` 为空即未认证（401）
3. 超管直接放行
4. 角色全部锁定 / 无菜单 → 403
5. 非 GET/OPTIONS 且非 `is_staff` → 禁止后台写操作
6. `RBAC_ROLE_MENU_MODE=True`（默认）：按 `RequestPermission('xxx')` 设置的权限码匹配菜单 `perms`；否则走 Casbin 插件

数据权限（`backend/src/common/security/permission.py`）：`filter_data_permission()` 按角色数据规则生成过滤条件（`${user_id}` / `${dept_id}` / `${now}` 模板变量），超管不过滤。

### 5.4 依赖注入组合

| 注入 | 用途 |
| --- | --- |
| `DependsJwtAuth` | 已登录即可访问 |
| `DependsSuperUser` | 仅超级管理员 |
| `DependsRBAC` | 角色菜单权限（配合 `RequestPermission('xxx')` 声明权限码） |
| `RequestPermission` | 声明接口权限标识，注入 `ctx.permission` |
| `CurrentSession` / `CurrentSessionTransaction` | 数据库会话注入（见 [数据库层设计](数据库层设计.md) 第 5 节） |

## 6. 中间件与白名单

- `JwtAuthMiddleware`（`backend/src/middleware/jwt_auth_middleware.py`）实现 Starlette `AuthenticationBackend`：
  - `extract_token`：仅处理 `Authorization: Bearer`，白名单路径直接跳过
  - `authenticate`：`jwt_authentication` 成功返回 `AuthCredentials(['authenticated']) + user`
  - 认证异常：`TOKEN_REQUEST_UNDERLYING_SECURITY=True` 时按 401 返回，否则缓存异常由路由依赖抛出
- 注册与执行顺序见 `register_middleware`（`backend/src/core/register.py`，注释明确「执行顺序从下往上」）：
  CORS → 请求上下文（request_id）→ 访问日志 → i18n → **JWT 认证** → 请求状态 → 操作日志
- 白名单配置：`TOKEN_REQUEST_PATH_EXCLUDE`（默认仅 `/api/v1/auth/login`）与 `TOKEN_REQUEST_PATH_EXCLUDE_PATTERN`

## 7. SSO 设计（第三方登录）

### 7.1 定位与形态

- 插件目录：`backend/src/plugin/oauth2/`，基于 `fastapi_oauth20`（GitHub / Google）
- **当前 SSO 形态**：第三方社交登录（OAuth 2.0 授权码模式），解决「外部身份 → 系统账号」的免密登录与绑定
- **未接入**：企业级联合 SSO（OIDC / SAML / LDAP）——如需要统一企业目录登录，属后续扩展（见 7.6 缺口）
- SSO 登录成功后复用统一的 JWT 会话体系（access/refresh + Redis），与账号密码登录无差别

### 7.2 登录流程（授权码模式）

```text
1. GET /api/v1/oauth2/{provider}            前端获取授权链接
2. 生成随机 state → Redis 存 {type: login}（3 分钟过期）
3. 302 跳转 GitHub / Google 授权页
4. 用户授权后回调 /api/v1/oauth2/{provider}/callback
5. FastAPIOAuth20 依赖兑换 access_token → 拉取用户信息
6. login_or_binding()：校验 state（一次性）→ 按 sid 查 sys_user_social
7. 已绑定：直接登录；未绑定：按 email 匹配系统用户，无则自动注册
8. 统一 create_access_token + create_refresh_token（写 HttpOnly Cookie）
9. 302 跳转前端：{FRONTEND_LOGIN_REDIRECT_URI}?access_token=xxx&session_uuid=xxx
```

### 7.3 绑定与解绑

| 场景 | 端点 | 说明 |
| --- | --- | --- |
| 查看绑定 | `GET /api/v1/oauth2/me/bindings` | 返回已绑定平台列表 |
| 获取绑定链接 | `GET /api/v1/oauth2/me/binding?source=github` | `state` 中写入 `{type: binding, user_id}` |
| 回调绑定 | `{provider}/callback` | 校验 `user_id` 后写入 `sys_user_social` |
| 解绑 | `DELETE /api/v1/oauth2/me/unbinding?source=github` | 删除绑定关系 |

绑定约束（`user_social_service.binding_with_oauth2`）：

- 同一用户同一平台不可重复绑定
- 同一第三方账号（`sid + source`）已被他人绑定时拒绝

### 7.4 用户映射与自动注册

- 绑定表：`sys_user_social`（`sid` / `source` / 逻辑外键 `user_id`，`(sid, source)` 唯一）
- 登录匹配顺序：先按 `sid` 查绑定 → 无则按 `email` 匹配系统用户 → 仍无则自动注册
- 自动注册：密码为空（`password=None`）、默认 `is_staff=True`；用户名冲突时追加随机后缀重试（最多 10 次）
- 首登更新头像（用户无头像时）
- 平台字段映射差异在 `login_or_binding` 中统一收敛（如 GitHub 取 `id/login/name`，Google 取 `id/name/given_name/picture`）

### 7.5 安全要点

| 要点 | 实现 |
| --- | --- |
| CSRF 防护 | `state` 随机生成 + Redis 存储 + **一次性消费**（校验后即删） |
| state 有效期 | `OAUTH2_STATE_EXPIRE_SECONDS`（默认 180s） |
| 回调限流 | `RateLimiter(5/min)` 防暴力回调 |
| 令牌泄露面 | access token 走 URL 参数回传前端（302 场景折中，需 HTTPS 保障） |
| 绑定权限 | 绑定接口全部 `DependsJwtAuth`，且 `state` 内绑定 `user_id` 防止串绑 |
| 客户端密钥 | `OAUTH2_*_CLIENT_SECRET` 仅存服务端 env，不落前端 |

### 7.6 配置项

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `OAUTH2_GITHUB_CLIENT_ID/SECRET` | 必填 | GitHub OAuth App 凭据 |
| `OAUTH2_GOOGLE_CLIENT_ID/SECRET` | 必填 | Google Cloud OAuth 凭据 |
| `OAUTH2_GITHUB_REDIRECT_URI` | `http://127.0.0.1:8000/...` | 后端回调地址，**部署替换为真实域名** |
| `OAUTH2_GOOGLE_REDIRECT_URI` | 同上 | 后端回调地址 |
| `OAUTH2_FRONTEND_LOGIN_REDIRECT_URI` | `http://localhost:5173/oauth2/callback` | 登录后前端落地页 |
| `OAUTH2_FRONTEND_BINDING_REDIRECT_URI` | `http://localhost:5173/profile` | 绑定完成后前端落地页 |
| `OAUTH2_STATE_EXPIRE_SECONDS` | 180 | state 有效期 |

> 部署配置见 [配置清单](配置清单.md)（`OAUTH2_*` 行）；生产环境 `your-domain` 占位必须替换。

| 密码哈希 | ✅ | pwdlib + bcrypt，含复杂度/历史/过期/锁定策略 |

## 9. 已知缺口

- **access token 明文存 Redis**：换取即时撤销，代价是每个请求一次 Redis 读；高并发下可评估改用无状态 JWT + 撤销清单
- **`OAuth2PasswordBearer` 未接入 Swagger 授权按钮**：Swagger 调试使用独立的 `/auth/login/swagger`（HTTP Basic）快捷登录
- **JWT 用户缓存**：`get_jwt_user` 有 TODO（`model_validate_json` 替换），缓存一致性依赖 `TOKEN_EXPIRE_SECONDS` 窗口
- **企业级 SSO 未接入**：当前仅 GitHub / Google 社交登录；如需 OIDC / SAML / LDAP 统一身份源，需扩展 `fastapi_oauth20` 之外的适配器（见 7.1）
- 第三方登录回调 URI 为占位值，上线前必须替换（见 [配置清单](配置清单.md)）
