# 环境变量

## 1. 分层架构

项目中的 env 文件分三层，职责互不重叠：

| 层级 | 文件 | 谁读取 | 内容 |
| --- | --- | --- | --- |
| ① 编排层 | 根 `.env` | `docker-compose.yml` | 容器账号、端口映射、日志挂载路径 |
| ② 应用层（本地） | `backend/src/.env` | 后端进程（`backend/src/core/config.py`） | 应用配置，host 为 `localhost` |
| ③ 应用层（部署） | `deploy/backend/docker-compose/.env.server` | 容器内后端进程（挂载为 `backend/src/.env`） | 应用配置，host 为容器名（`ragf_postgres` 等） |

另有插件级示例（不参与主流程）：`backend/src/plugin/{email,oauth2}/.env.example`。

## 2. 重复字段与单一事实源

账号类字段存在跨层重复（容器创建需要、应用连接也需要），**单一事实源是根 `.env`**：

| 根 `.env` | 应用层字段（② ③ 保持一致） | 说明 |
| --- | --- | --- |
| `POSTGRES_USER` | `DATABASE_USER` | 数据库账号 |
| `POSTGRES_PASSWORD` | `DATABASE_PASSWORD` | 数据库密码 |
| `RABBITMQ_USER` | `CELERY_RABBITMQ_USERNAME` | RabbitMQ 账号 |
| `RABBITMQ_PASSWORD` | `CELERY_RABBITMQ_PASSWORD` | RabbitMQ 密码 |

修改根 `.env` 的账号后，必须同步更新 `backend/src/.env` 与 `.env.server`，否则容器创建成功但应用连不上。

## 3. 一致性校验

```bash
task env:check
```

自动比对三层 env 的账号字段并给出结果；不一致时以非零退出并提示需同步的文件。

## 4. 各层注意事项

- **根 `.env`**：不提交敏感值（`POSTGRES_PASSWORD` 等由 `.env.example` 模板填写）；`.env` 本身应留在 `.gitignore`
- **`backend/src/.env`**：本地开发专用，已加入 `.gitignore`；从 `backend/src/.env.example` 复制生成
- **`.env.server`**：部署专用，其中 `TOKEN_SECRET_KEY` 等必须更换为独立生成的值（`secrets.token_urlsafe(32)`）
- 配置读取优先级（`backend/src/core/config.py`）：真实环境变量 > `.env` 文件，生产环境可直接用环境变量注入
