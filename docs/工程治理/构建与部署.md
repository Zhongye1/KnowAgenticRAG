# 构建与部署

## 1. 构建 Python 安装包（wheel / sdist）

```bash
task build        # 等价于 backend 目录下执行 uv build
```

产物输出到 `backend/dist/`：

| 产物 | 说明 |
| --- | --- |
| `backend-<版本>-py3-none-any.whl` | 可安装的 wheel 包 |
| `backend-<版本>.tar.gz` | 源码分发包（sdist） |

版本号取自 `backend/__init__.py` 中的 `__version__`。

### wheel 包含的内容

由于 `backend` 包即项目根目录自身（`backend/__init__.py` 位于 pyproject 所在目录），
`pyproject.toml` 通过 `[tool.hatch.build.targets.wheel."force-include"]` 将以下内容映射进 wheel 的 `backend/` 包：

- `backend/__init__.py`、`backend/main.py`
- `backend/src/` 下的核心模块：`app`、`common`、`core`、`database`、`middleware`、`plugin`、`sql`、`static`（含 ip2region 离线库）、`utils`、`alembic`、`locale`
- `backend/src/.env.example`（配置示例）

**不会打包**：开发环境文件（`.env`、`src/.env`）、运行时日志（`src/log/`）、测试（`src/tests/`）、
构建产物（`dist/`）、虚拟环境（`.venv/`）以及 Taskfile / scripts / run.py 等开发辅助文件。

### 安装 wheel

```bash
uv pip install backend/dist/backend-1.15.1-py3-none-any.whl
```

生产部署时不要依赖包内的 `.env.example`，直接通过**环境变量注入配置**
（`backend/src/core/config.py` 的配置源优先级为：真实环境变量 > `.env` 文件）：

```bash
export DATABASE_HOST=... DATABASE_USER=... DATABASE_PASSWORD=... REDIS_HOST=... TOKEN_SECRET_KEY=...
```

## 2. 构建 Docker 镜像

项目提供多阶段 `Dockerfile`（基于 uv 构建 + 精简运行镜像）：

| 镜像 | 说明 |
| --- | --- |
| `ragf_server` | FastAPI 服务（supervisord 托管） |
| `ragf_celery_worker` | Celery Worker（gevent 协程池） |
| `ragf_celery_beat` | Celery 定时任务调度器 |
| `ragf_celery_flower` | Celery 监控面板 |

```bash
task docker-build                                              # 构建全部应用镜像
task docker-build DOCKER_SERVICES=ragf_server                  # 构建单个服务
```

等价命令：

```bash
docker compose build ragf_server ragf_celery_worker ragf_celery_beat ragf_celery_flower
```

完整部署编排见 `docker-compose.yml`（依赖 + 应用 + 可观测性栈：Loki / Prometheus / Tempo / Grafana / Alloy）。

## 3. 依赖与锁定

- 依赖声明：`backend/pyproject.toml`，精确锁定：`backend/uv.lock`（Docker 构建使用 `uv sync --locked`）
- 导出 requirements.txt（非 uv 环境部署用）：`task backend:export`

## 4. 发布到私有索引（可选）

```bash
cd backend
uv publish  # 需配置 UV_PUBLISH_URL / UV_PUBLISH_TOKEN，或 ~/.config/uv/uv.toml
```

## 5. 部署检查清单

- [ ] 配置通过环境变量注入，或挂载 `.env` 到容器内 `backend/src/.env`
- [ ] `src/static/` 上传目录使用持久卷挂载（compose 中 `ragf_static_upload`）
- [ ] 日志目录挂载持久卷（compose 中 `${DOCKER_RAGF_SERVER_LOG:-./logs/ragf}`）
- [ ] 首次启动后端自动建表（`create_all`）；需要种子数据时执行初始化 SQL
