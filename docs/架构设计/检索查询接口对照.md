## 1. EagleRAG 接口设计列表

### 1.1 REST 查询面(query 路由组,无前缀挂载,无认证中间件)

#### `POST /search` — 纯检索(同步)

**SearchRequest**

| 字段              | 类型            | 说明                                                       |
| ----------------- | --------------- | ---------------------------------------------------------- |
| `query`           | `str = ''`      | 查询文本(与 attachments 至少其一)                         |
| `plugin_namespace`| `str?`          | 生产环境必须与实例 namespace 一致否则 403                  |
| `mode`            | `str?`          | `auto \| text \| visual \| hybrid`(auto 走路由决策)       |
| `kb_name`         | `str?`          | 知识库标识(多租户)                                        |
| `attachments`     | `list[str]?`    | attachment_id 列表(**可检索的一等来源**)                   |
| `scope`           | `list[str]?`    | 限定这些 document_id                                       |
| `filters`         | `QueryFilters?` | 标量过滤                                                   |
| `scope_filter`    | `ScopeSelection?` | 高级范围过滤(kb/documents/tags **并集**)                 |

**QueryFilters**:`source_type?`(文档来源类型)/ `pipeline?`(`knowhere | pixelrag`)/ `year?`(int)——直推 Milvus 标量。
**ScopeSelection**:`kb_names[]` / `document_ids[]` / `tags[]`——三者 OR 并集,可跨库。

**SearchResponse**

| 字段      | 类型              | 说明                                        |
| --------- | ----------------- | ------------------------------------------- |
| `sources` | `QuerySources`    | `text: TextSource[]` + `image: ImageSource[]` 二元来源模型 |
| `route`   | `RouteInfo`       | 路由决策(mode/selected/reason/kb_name;selector ∈ `forced\|attachment\|llm\|heuristic\|default`) |
| `steps`   | `list[QueryStep]` | 过程轨迹:`{name: route\|recall\|rerank, detail}`        |

**TextSource**(关键字段):`type(text|table|image|section_summary)` / `path` / `level` / `document_id` / `score` / `source(kb|attachment)` / `attachment_id` / `file_name` / `content`(table 块携带 HTML)/ `summary` / `keywords[]` / `page_nums[]` / `file_path` / `document_top_summary` / `chunk_count` / `kb_name` / `source_type`。

**ImageSource**(关键字段):`type=image` / `image_id` / `image_path` / `page` / `position` / `document_id` / `score` / `source(kb|attachment)` / `file_name` / `chunk_type(tile|image|table)` / `parent_section` / `content_summary` / `source_chunk_id` / `kb_name` / `year`。

#### `POST /search/stream` — 纯检索 SSE

事件:`step | sources | done | error`(`error: {code, message}`;done 携带最终 sources)。实现为 queue+thread 桥接同步引擎。

#### `POST /query` — 检索 + 生成(同步)

**QueryRequest** = SearchRequest + `session_id?`(**缺省自动建会话**)。生成参数(模型/温度)不在请求内,服务端配置决定。
**QueryResponse**:`session_id` / `message_id`(assistant 消息)/ `answer` / `sources` / `route` / `steps`。回答与来源持久化为 assistant 消息,持久化失败非致命(追加 `warning` step)。

#### `POST /query/stream` — 问答 SSE

事件:`session | step | sources | token | done | error`(检索阶段推 step/sources,生成阶段推 token)。

#### 会话资源

`GET/POST/PATCH/DELETE /sessions`、`GET /sessions/{id}/messages`(分页)。
- `SessionCreate{title?, kb_name?}`
- `SessionSummary{session_id, title, kb_name, scope_filter, created_at, updated_at}`(scope_filter 记住最近一次范围选择)
- `MessageOut{message_id, session_id, role, content, sources, steps, attachments, kb_name, created_at}`

### 1.2 支撑面(与 query 强相关)

- **附件**:`POST /attachments`(上传)、`GET /attachments/{id}`、`GET /attachments/{id}/content`、`DELETE`。`AttachmentOut{attachment_id, session_id?, file_name, mime, size_bytes, expires_at, created_at}`(storage_path 对外隐藏)。
- **文档**:`GET /documents`(分页)/ `/{id}` / `/{id}/structure` / `/{id}/file` / `/{id}/chunks/{chunk_id}`(chunk HTML 渲染)/ `DELETE`。
- **图像回源**:`GET /images/{image_id}/content`、`GET /images/{image_id}/meta`——视觉 tile 直接回源。
- **摄取**:`POST /ingest`(+ `/ingest/validate/file`、`/ingest/validate/url` 预检)、`GET /ingest/queue-metrics`、`GET /tasks`、`GET /tasks/{job_id}`(任务审计)。

### 1.3 MCP 工具面(FastMCP,4 工具)

| 工具             | 入参                                                                                  | 返回                              |
| ---------------- | ------------------------------------------------------------------------------------- | --------------------------------- |
| `ingest`         | file / url 写工具                                                                     | 任务受理结果                      |
| `query`          | `query?, mode?, scope?, kb_name?, scope_filter?, image_base64?, image_mime?`          | `{answer, sources, route, steps}` |
| `retrieve_text`  | `query, scope?, top_k=5, kb_name?`                                                    | `[{node_id, text, score, metadata}]` |
| `retrieve_visual`| `query?, image_base64?, image_mime?, scope?, top_k=5, kb_name?`(**支持以图检索**)    | Top-K 视觉 tile                   |

特性:结果缓存(cache_key 命中跳过检索+精排)、`with_metrics` 埋点、`record_mcp_call` 审计;无独立鉴权层(PAT/scopes 均无)。

### 1.4 横切

无认证中间件(注释明示"内网部署");仅 `plugin_namespace` 请求头校验;SSE 统一以 `queue.Queue + threading` 桥接同步引擎;响应为裸 Pydantic 模型(无统一包装)。

## 2. RAG-F 当前接口设计(query 面)

### 2.1 REST

#### `POST /api/v1/knowledge_bases/{kb_name}/search`(JWT + RBAC `rag:kb:search`)

**KBSearchParam**(全部可选覆盖,三层合并 request > KB `query_params` > settings)

| 字段                   | 类型/范围             | 默认(settings)                          |
| ---------------------- | --------------------- | ----------------------------------------- |
| `query_text`           | `str` 1..2000 必填    | —                                         |
| `search_mode`          | `vector \| hybrid`    | `hybrid`                                  |
| `recall_top_k`         | `int` 1..200          | 20                                        |
| `final_top_k`          | `int` 1..50           | 5                                         |
| `similarity_threshold` | `float` 0..1          | 0.2(仅 vector)                          |
| `use_reranker`         | `bool`                | true                                      |
| `include_visual`       | `bool`                | false(视觉召回,§4.1)                  |
| `visual_top_k`         | `int` 1..50           | 5                                         |
| `file_name`            | `str?` ≤255           | —                                         |
| `filters`              | 见下                  | —                                         |

**RetrievalFilters**:`keyword?` / `tag?` / `version_id?`(精确版本)/ `updated_after?` / `updated_before?` / `file_type?` / `path_prefix?`——文档级条件经 PG 登记解析为 document_id 集(命中 >500 报错),version_id 直推 Milvus 标量。

**KBSearchOutput**(fba `{code, message, data}` 包装内)

| 字段              | 说明                                                                     |
| ----------------- | ------------------------------------------------------------------------ |
| `kb_name(s)`      | 库标识                                                                   |
| `mode`            | 实际生效模式                                                             |
| `recall_count`    | 精排前候选数                                                             |
| `reranked/degraded` | 精排是否生效/是否降级                                                  |
| `duration_ms`     | 耗时                                                                     |
| `results[]`       | `SearchHitItem{chunk_id, document_id, kb_name, version_id, chunk_index, content, metadata{source, score, rerank_score, token_count}}` |
| `visual_results[]`| `VisualHitItem{id, image_path(对象键), document_id, kb_name, page, position, chunk_type, parent_section, content_summary, score}` |
| `visual_degraded` | 视觉召回失败降级标记                                                     |

#### `POST /api/v1/knowledge_bases/{kb_name}/chat`(SSE,D25 事件协议)

**ChatParam**:`query_text` + 生成参数(`model?`、`thinking_level?`、`temperature?`、`max_tokens?`)+ 会话(`history[]` 显式传、`attachments[]` ≤4 个**纯文本**随问附件)+ 检索覆盖键(与 search 同,含 `include_visual/visual_top_k`)。
事件:`meta{kb_name, mode, model_spec, hit_count, visual_count}` → `citation{citations[]}` → `delta{content}`* → `usage{prompt_tokens, completion_tokens, total_tokens}` → `done{reason}`;错误统一 `error{code, msg, trace_id}`。
**CitationItem**(纯 chunk 语义):`n`(连续编号,对应回答 `[n]`)、`kb_name`、`document_id`、`version_id`、`chunk_id`、`source`、`score`、`content`。

#### 支撑面

- kb:`/knowledge_bases` CRUD(`query_params` 白名单 7 键持久化)、ACL、`/overview`、`/{kb}/facets`;`/documents` 下载(预签名 URL)/详情/替换/删除;`/tags`。
- ingest:`POST /{kb}/documents`(上传+登记+关口,两段式第一步)、`POST /{kb}/documents/{document_id}/ingest`(仅派发,第二步)、`GET status`、`POST /{kb}/rebuild`;不支持 URL 摄取。
- 无会话资源、无检索流式端点、无独立 images 回源端点。

### 2.2 MCP 工具面(5 工具,全只读)

PAT 鉴权 + scopes(`rag:kb:list/search/read/chat`)+ 限流 + `mcp_call_log` 审计;工具只编排 service 门面(D30)。

| 工具                   | 入参                                                        | 返回                          |
| ---------------------- | ----------------------------------------------------------- | ----------------------------- |
| `list_knowledge_bases` | —(随身份)                                                 | 可见库列表                    |
| `search_knowledge`     | `query_text, kb_names[], top_k?, use_reranker?, file_name?, filters?` | 带引用字段命中(**多 KB**) |
| `answer_with_citations`| ChatParam 投影 + `kb_names[]`                               | `{answer, citations, usage}`  |
| `read_document_chunks` | 文档/版本 + chunk 窗口                                      | chunk 列表                    |
| `get_document`         | document_id                                                 | 定位元数据(active_version)  |

### 2.3 横切

JWT + RBAC + 路由权限点;scope 服务端构建(客户端不可传过滤语义),ACL 三层下推(Milvus 表达式);fba 统一响应包装;OTel 全链路;文档版本化(`version_id`/`active_version` 收敛)。

## 3. RAG query 差别综合

| # | 维度         | EagleRAG                                                        | RAG-F 现状                                                      | 评价/方向                                                    |
| - | ------------ | --------------------------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------ |
| 1 | 入口组       | search(+stream)/ query(+stream)四端点                          | search(同步)/ chat(SSE)两端点                                  | RAG-F 检索无流式(检索是短操作,可接受)                     |
| 2 | KB 定位      | body `kb_name` + `scope_filter{kb_names, document_ids, tags}` **并集跨库** | 路径 `{kb_name}` 天然单库;跨库仅 MCP `search_multi`            | **REST 跨库是明显不对称**,可借鉴并集语义                     |
| 3 | 策略选择     | `mode=auto` + RouteDecision(selector=forced/attachment/llm/heuristic/default) | 显式参数 `search_mode` + `include_visual`,无路由             | 显式参数成本可控;auto 路由等评估集后再议                     |
| 4 | 过滤模型     | 标量直推(`source_type/pipeline/year`)                           | 文档管理语义(keyword/tag/updated/file_type/path_prefix)解析为 doc_id 集 + 500 上限 | RAG-F 更严(防拉全库);EagleRAG 更"检索器原生"               |
| 5 | 多模态输入   | **支持图片查询**:`query_image_bytes`(REST 附件/MCP `image_base64`),文+图双路 max 合并 | 仅文本查视觉集合                                              | 以图搜图是 EagleRAG 独有能力,待多模态场景                    |
| 6 | 附件语义     | 一等检索源(`source: kb\|attachment`)                            | 仅随问文本注入 prompt                                           | 按 RAG-F 非目标取舍(D18 期)                                 |
| 7 | 来源模型     | `sources{text[], image[]}` 二元契约,ImageSource 含 `content_summary/source_chunk_id` | `results(chunk)` 主 + `visual_results` 独立段(字段已对齐 ImageSource,summary/chunk_id 摄取侧为空) | 已收敛;缺摄取侧元数据填充                                   |
| 8 | 过程可解释   | `route/steps` 进响应体(前端可直接展示决策)                     | 标量(`reranked/degraded/duration_ms`),轨迹在 OTel              | 借鉴 route/steps 入响应,调试/展示双赢                        |
| 9 | 流式范围     | 检索也流式(step/sources)                                        | 仅问答流式(D25)                                               | —                                                             |
| 10 | 会话        | sessions/messages 资源 + query 自动建会话 + scope_filter 记忆    | 无服务端会话,history 显式传(D18 非目标)                      | 待会话持久化设计                                              |
| 11 | 生成控制    | QueryRequest 无模型参数(服务端定)                              | ChatParam 带 `model/temperature/max_tokens/thinking_level`     | RAG-F 更灵活,EagleRAG 更收敛                                 |
| 12 | 引用契约    | sources 无 [n] 编号字段                                         | D24:`n` 连续编号 + 回答 `[n]` 标注 + token 预算裁剪            | RAG-F 契约更强;扩展 image 引用即"回答带图"路径             |
| 13 | 图像回源    | `images/{id}/content|meta` 端点                                 | **缺**(visual_results 只有对象键)                            | 最优先补齐,`presigned_get_object` 已就位                    |
| 14 | 版本化      | 无版本概念(`year/source_type` 维度)                            | `version_id` 精确过滤 + `active_version` 收敛                  | RAG-F 独有                                                    |
| 15 | 鉴权        | 无(内网)                                                      | JWT/RBAC/权限点;MCP PAT+scopes+限流+审计;ACL 三层下推         | RAG-F 强;代价是 scope 只能服务端构建                        |
| 16 | MCP 面      | 4 工具含 **ingest 写工具** + 结果缓存;无鉴权                    | 5 工具全只读 + PAT/scopes/审计                                 | 定位不同:RAG-F 面向工程师 Agent 的只读闭环(D30)           |

## 4. 收敛建议(按性价比)

1. **images 回源端点**(EagleRAG §1.2):`visual_results` 已回对象键,补端点即可渲染,`presigned_get_object` 现成;
2. **REST 跨库查询**(EagleRAG `scope_filter` 并集语义):补齐"REST 单库 / MCP 跨库"不对称;
3. **route/steps 轨迹入响应**:与 OTel 不冲突(面向人 vs 面向机器);
4. MCP `retrieve_visual` 带图输入、查询路由(mode=auto):等场景与评估集成熟。
