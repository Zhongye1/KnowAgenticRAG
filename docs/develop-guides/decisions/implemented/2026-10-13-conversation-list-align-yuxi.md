# 侧边栏的会话列表对齐参照

状态：implemented
类型：feature
Owner：web/src/features/chat/ui/conversation-list.tsx

事实分工：本记录拥有会话列表的**行结构、手势与几何**（32px 行、悬停遮罩、「更多」按钮、状态点与置顶标记的位置）与**折叠标题**。`web/src/features/chat/model/thread-list-store.ts` 拥有分页状态（`THREAD_PAGE_SIZE` / `hasMore` / `loadingMore` / `loadMore`）；`web/src/features/chat/ui/conversation-list.module.css` 拥有视觉值。

## 问题

会话列表此前只对齐了参照的文案与 store 语义，形态与交互都走样：

- 没有参照的「最近」折叠标题（`.history-label`）。
- 行是「链接 + 悬停菜单」；参照还有**双击重命名**与**中键删除**两套手势。
- 重命名是行内输入框；参照是弹窗（标题「重命名对话」、说明「保持简短且易于识别」、保存/取消，空标题给提示）。
- **没有分页**：后端 `GET /api/chat/threads` 的 `limit` 默认 100，本仓不传 `limit`，因此超过 100 条会话会被静默截断，用户看不到更早的会话；参照有「加载更多」（`PAGE_SIZE = 100`，按 `offset` 追加、按 id 去重、以「上一页是否装满」推断还有没有下一页）。
- 行几何与参照不同：参照是 32px 高、8px 圆角、13px、`--gray-700`，状态点绝对定位在右侧且悬停时让位给「更多」按钮；本仓是 Tailwind 的 `px-2 py-1 text-sm`，状态点与置顶标记挤在行内。
- 悬停时没有参照的渐隐遮罩（`.actions-mask`），标题会从按钮下面穿出来。
- 「更多」菜单没有图标、顺序是「重命名 / 置顶 / 删除」；参照是「置顶（Pin/PinOff）/ 重命名（SquarePen）/ 删除（Trash2）」。
- 会话行的标题带下划线：行是 `<a>`，本仓**不引 Tailwind 的 preflight**（`src/index.css` 只引 theme 与 utilities，重置交给 antd 的 `reset.css`），而 antd 的 reset 没有清 `a` 的下划线，于是 UA 默认生效。这是既有问题——改动前的版本同样有下划线（用 `git stash` 换回旧文件在浏览器里核对过）；其余页面没有，因为只有这里的链接没有显式声明 `text-decoration`。
- 文案与结构细节：空态是「还没有历史会话。」（参照「暂无对话历史」）、占位是「未命名会话」（参照「新的对话」）；`<ul>` 的默认内边距把行挤窄（标题因此提前截断），默认项目符号也不是参照的样子。

## 决策

1. **加「最近」折叠标题**：参照是 clickable `div`，这里用 `<button type="button" aria-expanded>`——键盘用户需要能聚焦与回车，外观照参照（14px/600、`--gray-800`、4px 圆角）。
2. **行的手势与参照一致**：双击重命名、中键删除（拦下默认行为，否则浏览器另开标签页）、单击仍是 `<Link>` 导航。
3. **操作区是会话链接的兄弟节点**，绝对定位覆盖在右侧：`<a>` 里不能放按钮（无效 HTML），且嵌进去会让点「更多」冒泡成一次导航。
4. **重命名改成弹窗**：标题「重命名对话」、说明「保持简短且易于识别」、输入框自动聚焦、保存/取消，回车提交、Esc 关闭；标题为空时给提示且不关弹窗。
5. **行几何与状态照参照**：32px / 8px 圆角 / 13px / `--gray-700`；状态点（运行中转圈 12px、有新回复 6px 圆点，主色）绝对定位在右侧，悬停时让位给「更多」按钮；置顶标记占「更多」按钮的位置，未悬停时显示。
6. **「更多」菜单照参照**：置顶 / 取消置顶、重命名、删除，各带图标。
7. **补分页**：`THREAD_PAGE_SIZE = 100`，首屏显式传 `limit`；`hasMore` 由「上一页是否装满」推断（后端不返回总数）；`loadMore` 按 `offset = threads.length` 追加、按 id 去重（后端分页会重复返回置顶项）、`loadingMore` 与首屏 `loading` 分开，避免整列表退回加载态。
8. **去掉 `<ul>` 的默认内边距与项目符号**：默认 `padding-inline-start: 40px` 把行挤窄，标题因此比参照更早截断。
9. **文案照参照**：占位「新的对话」（也与本仓页头的用词一致）、空态「暂无对话历史」。

## 替代方案

**行改成参照的 `div`**：会丢掉可聚焦、可读屏、右键新标签页打开；手势挂在 `<Link>` 上、中键拦默认行为即可两者兼得。

**悬停/选中底色用参照的 `--gray-50`**：本仓侧边栏底色是 shadcn 的 `--sidebar`（偏冷的浅底），`--gray-50` 在上面几乎没有对比，悬停会看起来「没反应」；底色因此仍走 `--sidebar-accent`。

**「删除」菜单项去掉 `danger`**：参照没标，但破坏性动作需要可辨识的标记，本仓原本就标了，保留。

**加载中不显示等待文案、直接显示空态**：参照在加载期间就会闪一次「暂无对话历史」；本仓保留「正在加载会话…」，慢网络下不会先闪空态（已有用例覆盖）。

**删除确认交给父级**：参照把确认放在父级布局里；本仓的列表自己持有 store，就地确认更短，且「删掉当前会话要离开该地址」这条编排本来就与列表的当前项判断绑在一起。

## 后果

- 会话列表多出两套手势（双击重命名、中键删除）：中键删除是隐藏手势，键盘用户摸不到；删除仍有确认弹窗兜底。
- 首次加载改成显式 `limit=100`：超过 100 条的用户现在能看到「加载更多」，而不是被静默截断。
- 行的悬停/选中底色与本仓侧边栏调色板一致，但与参照的灰色不同——这是刻意的，见「替代方案」。
- 重命名从「行内编辑」变成「弹窗」，用户少了一次原地改名的路径。

## 风险

- 中键删除是隐藏手势：误触会打开删除确认（有二次确认兜底），但对不熟悉该手势的用户是意外。这是参照的行为，用户已明确选择照搬。
- `hasMore` 用「上一页是否装满」推断：恰好是 100 的整数倍时会多出一次「加载更多」，点下去返回空则按钮消失。后端不返回总数，这是可用的近似。
- 分页只在首屏与「加载更多」时生效；`upsert`（新建线程插到最前）与删除只改本地列表，不会打乱 `offset` 的语义（offset 用的是当前列表长度，插入会使下一页可能重复，去重按 id 兜住）。
