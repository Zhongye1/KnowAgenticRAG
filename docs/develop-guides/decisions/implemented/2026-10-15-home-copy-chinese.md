# 首页文案统一为中文

状态：implemented
类型：feature
Owner：web/src/pages/home/ui/home-page.tsx

## 问题

首页是从英文模板搬来的，正文（hero、能力段、流程控件、顶栏导航、页脚）全是英文，而后来新增的任务链段、知识总览段与数据源段是中文。同一页中英混排，且产品面向中文用户。

## 决策

1. 把首页可见文案统一为中文：hero 标题与描述、两个按钮、数据流控件的阶段名与说明、能力段的标题/用例/条目、顶栏导航项、页脚状态与链接。
2. 同时把只服务读屏与测试的可访问名改成中文：`主导航`、`打开/关闭导航菜单`、`数据流阶段选择`、`开放数据能做什么`、`平台数据范围`。
3. 保留不翻译的部分：品牌名 `KnowAgenticRAG`、`GitHub`、`MCP`/`API`/`CLI`/`RAG`/`Agent`/`Wiki` 等术语与缩写、产品截图的 `alt`（已是中文）、页脚的公司主体 `© 2026 Ausdata Science Pty Ltd`（专有名词，且它是模板带来的实体，是否改成自家主体是另一个决定）。
4. 知识总览段的英文眉标 `01 / KNOWLEDGE AT WORK` 与序号 `01 / RAG` 按参考图保留英文 —— 参考图本身是中文页，也照样用英文眉标。
5. 同步更新钉住旧英文文案的测试断言：`home-page.test.tsx` 里 hero 强调词与描述的匹配改指中文，测试名去掉「照搬」。

## 替代方案

- 只翻译新增段落、保留英文正文：那样一页两种语言，读起来是两套产品。
- 用 `i18n` 做多语言：仓库没有面向 C 端的运行时语言切换机制，为首页单独引入一套是过度设计。
- 顺手删掉/改写断言已删除段落的测试：那是组件删除那个决定的范围，不属于「整理文案」，留着由所有者决定。

## 后果

- 首页不再有可见英文（除品牌名与术语）。
- `home-page.test.tsx` 里仍失败的 5 条断言，失败原因仍是「找不到已删除段落的文案」，与本次语言整理无关；hero 粒子画布那条已随文案更新继续通过。
- 页脚仍挂着模板带来的公司主体名与 `/protocols/privacy-policy.template.html`，未在本次处理。

## 验证

- 5174 开发服务器实测：`#hero-title` 为「让智能工作 有据可依」、描述为中文、阶段名为「开放数据/向量流转/AI 上下文」、能力段标题为「开放数据 开箱即用」且首条为「发现」、页脚状态为「私有内测」、顶栏为「文档 | GITHUB ↗ | 进入控制台」。
- 门禁：`node scripts/check-design-tokens.mjs` 通过；`npx oxlint src` 仍为 `31 warnings and 3 errors`；`npx tsc --noEmit` 6 个错，均落在既有的 `workspace-ui.test.tsx` 与 `nexus-console.test.tsx`。
- 单测：`test/unit/pages/home-page.test.tsx` 5 failed / 3 passed，失败数与文案改动前一致（文案改动没有新增失败）。
