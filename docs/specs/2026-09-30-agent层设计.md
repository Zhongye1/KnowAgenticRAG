## 1. 目标与非目标

### 1.1 目标

1. **把 Agent 执行搬出 HTTP 请求**：建立持久化 Run 状态机 + FIFO 队列 + 租约，支持长任务与多副本；
2. **补齐失败护栏**：让「卡死、空转、截断、取消」四类失败**可复现地被终止或降级**，而不是烧完预算；
3. **建立工具注册表与门控**：工具可枚举、按能力与技能动态可见、MCP 工具按需发现；
4. **建立服务端产物与执行能力服务化**：报告类产物由服务端渲染与交付（带权限与版本）；转换/导出复用既有链路，补齐图表与报告渲染；
5. **落地技能**：`SKILL.md` 三级渐进披露 + 内容注入 + 依赖工具门控（**不投影文件系统**）。

### 1.2 非目标

- **不引入代码执行沙盒**（沿用 D86）：不跑客户脚本、不做文件工作台、不接 Docker/microVM 类沙盒服务；
- **不做多端与 IM Bot**（Web 为唯一客户端形态）；
- **不做 Text-to-SQL / 表格问答 / 推荐系统**；
- **不做 Agent 平权协作**（Multi-Agent / Hierarchical），长任务用**子智能体**；
- **本期不引 checkpointer、不做 run 级断点续跑**（D88）；
- **不做技能市场、版本共存与回滚**。

## 2. 总体架构

### 2.1 分层

```text
POST /{kb}/agent[/stream]                     ← API 层：提交 Run，立即返回 run_id 或直接进入 SSE
        │
        ▼
Run 提交层（agent/service/run_submission_service.py）  ← 校验 + 限流 + FIFO 判定
        │
        ▼
Run 状态机（agent_runs：8 态 + worker/lease/heartbeat） + FIFO 请求表（agent_run_request）
        │  Celery `agent` 队列（RAGF_CELERY_AGENT_QUEUE）
        ▼
RunWorker（agent/service/run_worker.py）        ← 取租约 → 心跳 → 执行图 → 终态写回
        │
        ▼
外层图（agent/graph）：plan → act ⇄ grade → rewrite → generate     ← 本项目差异点，保留
        ├── 内层 ReAct（LangChain create_agent）
        ├── 护栏层（§4.2 五类）
        └── 工具注册表（agent/toolkits）──┬─ 只读知识工具（现有 4 个收编）
                                          └─ MCP 工具（discover + call，④ Phase 4.1）
        │
        ▼
产物服务（workspace）：服务端渲染 → 登记 → MinIO → 权限/版本 → 下载/分享
        └── 执行能力服务化（§4.4）：Office 转换（复用 ① D55 容器）／整库导出（复用 kb.export_build）／图表渲染／报告渲染
        │
        ▼
SSE（D25 事件扩展：step/meta/citation/delta/usage/done/error + tool_call/tool_result/approval/artifacts/steer/compaction）
        └── 事件偏移重放（Redis List，TTL 1h）
```

### 2.2 一次 Run 的生命周期

```text
① 提交     校验 ACL/配额 → 生成 run_id → 创建消息 + RunRequest（同事务）→ 判活跃 Run 与队头
           → 立即派发 或 排队 或 拒绝（并发提交串行化）
② 接单     Worker 取租约（attempt ownership）→ 起心跳（独立事务）
③ 执行     跑图 → 工具调用（只读知识 / MCP）→ 需要产物时调服务端渲染
④ 护栏     迭代预算 + 五类失败护栏；取消/超时 → 合成已有结果
⑤ 收尾     产物登记 → 终态写回（CAS）→ 释放租约 → 写用量
⑥ 可观测   OTel 指标 + Grafana；审计只写变可读（`GET /runs/{id}`）
```

## 3. 关键决策（D87–D92）

| #       | 决策                                                                                                                                                                                        | 备选与否决理由                                                                                                                                                                                                                     |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **D87** | **执行能力服务化，不引入沙盒**：需要"执行"的能力一律以**无状态服务**提供——Office 转换复用 ① D55 转换容器、整库导出复用 `kb.export_build`、新增图表渲染与报告渲染；**产物由服务端生成**，不进任何执行环境 | 备选：引入沙盒（受限子进程 / 自建 microVM / 委托 OpenSandbox 等）。否决理由：当前目标（问答 + 深度调研 + 报告产物）**不需要跑代码、不需要文件工作台、没有第三方代码进入**；沙盒换来的能力当前无人使用，代价却是新基础设施 + 新失败点 + 生命周期管理 + 未验证的隔离档兼容性。触发条件见 §10 |
| **D88** | **不引入 checkpointer，不做 run 级断点续跑**（修订 ③ D64）：每轮从 DB 重建历史；压缩检查点落库；挂起（等审批/等索引）用**进程内阻塞 + Redis pub/sub**                                              | 备选：引 `AsyncPostgresSaver`（③ D64 原方案）。**修订理由**：WeKnora 在生产中以「每轮重建 + 压缩检查点」运行且无 checkpointer，证明该路线成立；我们的挂起点只有两个且都可由 pub/sub 解决。触发条件：出现「跨进程挂起 > 数分钟」或「需要图状态快照做回放/对比」时重新评估 |
| **D89** | 事件恢复用**偏移重放**，不引 seq：事件 append 进 Redis List（TTL 1h），重连从 offset 0 全量重放 + 轮询增量，重放前按 `event_id` 合并 delta                                                        | 备选：`Last-Event-ID` + seq（Yuxi）。否决理由：需引入 seq 生成与保序，收益仅在省带宽；本项目事件量小，WeKnora 同规模下用全量重放已够。触发条件：单事件流 > 1 万帧或重放带宽成为问题                                                        |
| **D90** | 工具面 = **全量注册 + 可见性门控**（④ D74/D76）**+ MCP 按需发现 + `tool_ref = sha256(serviceID+name+schema)` 校验**（仅允许调用已 describe 的工具）                                             | 备选：全量预加载 MCP 工具。否决理由：工具数随接入 server 增长，会挤占上下文并增加误调用；`tool_ref` 同时防「模型幻觉调用不存在的工具」与「schema 漂移」                                                                                 |
| **D91** | 审批 = **`ask_question` 单事件协议**（Mira）**+ 批准后执行前二次校验 + 审批等待不占用工具执行超时**（WeKnora）；对象 = **外部 MCP 写工具**                                                        | 备选：按工具名硬编码 `interrupt_on={...}`（Yuxi）。否决理由：工具集会随 MCP 接入变化，硬编码必然过期；备选：工具内自查（WeKnora 现状）——我们要求**权限与审批收口一处**，不散落到工具实现内                                                      |
| **D92** | 取消/超时语义 = **合成已有结果并落库**（连接通常已断，故这是落库问题而非推送问题）；终态由**显式原因**决定，不由「缺哪个事件」倒推                                                                     | 现状（`_outcome` 以 `meta_hits is None` 推断 cancelled）会丢弃已收集的检索与工具结果，且把「meta 之前的任何失败」误记为取消。WeKnora 在 ctx 取消时会先合成已有工具结果                                                                    |

## 4. 详细设计

### 4.1 Run 运行时

**状态机（8 态，沿用 ③ D70）**：`queued / running / waiting_ingest / interrupted / cancel_requested / cancelled / completed / failed`。

- **FIFO**：`agent_run_request` 按 `(uid, agent_slug, thread_id)` 排队 + 自增 id 定序；同事务创建消息与请求；锁会话后派发队头；
- **attempt 归属**：`agent_run_attempt(run_id, attempt_no, worker_id)` 唯一约束 → 重复投递不双跑；
- **租约**：Redis 取租约 + 独立事务续租 heartbeat；租约过期幂等收敛为 `failed`；Celery 只做投递，**事实源始终在 PG**；
- **取消**：Redis key + pub/sub；
- **API**：`GET /runs/{id}`（状态 + 用量 + 轨迹）、`POST /runs/{id}/cancel`。

### 4.2 图编排与护栏

外层图**结构不动**（`plan → act ⇄ grade → rewrite → generate`）。护栏新增五类：

| 护栏               | 规则                                                    | 理由（来自 WeKnora 生产常量）                     |
| ------------------ | ------------------------------------------------------- | ------------------------------------------------- |
| **stall ≠ total**  | 单轮流式 **120s 无输出**才终止；总时长另有上限           | 按总时长杀会丢掉「持续输出但耗时长」的轮次        |
| **空回复重试**     | 模型返回空且自然停止 → 重试 **2** 次                     | 防 thinking-only 空转                             |
| **同文重复**       | 连续 **2** 轮回复逐字相同且无工具调用 → 终止             | 未处理 finish reason 导致的卡死循环               |
| **连续截断**       | 连续 **3** 轮被 completion cap 截断 → 终止               | 防「模型重发更长的调用 → 再截断」的烧预算循环     |
| **截断调用不执行** | 被截断的那一批 tool_call **整批拒绝执行**，回灌结构化错误 | 半截参数执行等于让工具收到残参数                  |

**预算**：保留现有三重（`recursion_limit` / 墙钟 / `max_rewrites`），新增护栏与其正交；`RAGF_AGENT_TIMEOUT_SECONDS` 由「请求墙钟」改为「Run 墙钟」。

**取消/超时（D92）**：捕获取消 → 用已收集的 hits/steps 合成终态 → **落库**（`agent_runs.steps`）→ 释放租约。

### 4.3 工具面

**两类工具**：

| 类       | 工具                                                                                 | 注册方式                  |
| -------- | ------------------------------------------------------------------------------------ | ------------------------- |
| 只读知识 | `list_knowledge_bases` / `search_knowledge` / `read_document_chunks` / `get_document` | 静态注册（现有 4 个收编） |
| MCP      | `discover_mcp_tools` / `call_mcp_tool`（+ 动态 `mcp_{server}__{tool}`）                | 运行期注册，按需发现      |

**门控（④ D74/D76）**：全量注册进 ToolNode → 中间件**每次模型调用前**按 `已授权能力 ∩ 已激活技能依赖` 过滤 `request.tools`。

**MCP 接入（D90）**：`discover` 返回工具描述并生成 `tool_ref`；只有已 describe 的 ref 才可 `call`；命名 `{server}__{tool}`（分隔符防撞）+ 注册同名 first-wins 防劫持；**凭证在工具层不可见**，建连时注入。

**权限**：继续收口 `ToolContext`（工具 handler 内强制 ACL，延续 D33）。

> **关于扩展性**：工具注册表是**未来任何执行能力的唯一插槽**。若将来触发沙盒需求（§10），只需注册新的工具集，**无需重构工具面**——这是本期不引入沙盒却仍保留升级空间的关键。

### 4.4 执行能力服务化与产物服务（D87）

**能力清单**：

| 能力                          | 实现                                                              | 状态    |
| ----------------------------- | ----------------------------------------------------------------- | ------- |
| Office → PDF 预览             | 复用 `kb.preview_convert` + `preview_converter.py`（已有独立队列） | ✅ 已有 |
| 批量 / 整库导出               | 复用 `kb.export_build` + `kb_exports` 表                          | ✅ 已有 |
| 图表渲染                      | 服务端渲染，复用**同一个转换容器镜像**                            | 🆕      |
| 报告渲染（MD → HTML/PDF/DOCX） | 新增一个无状态渲染服务                                            | 🆕      |

**产物服务**：

- **模型**：`artifacts(slug, permission, allowed_users, source_run_id, version)` + 版本表（对齐 Mira `Artifact`）；
- **存储**：MinIO 对象键 `{tenant}/{project}/{artifact}/v{n}`；
- **生成**：由服务端渲染（Agent 只产出结构化内容：Markdown 正文 + 引用 + 图表数据）；
- **交付**：列表 / 下载 / 分享句柄；**产物是租户资产**（进配额，不随会话删除）；
- **红线**：渲染服务必须做**输入校验**（文件类型与体积白名单、禁外链回源）——这是 D87 取代沙盒后唯一新增的执行类组件，风险从「沙盒逃逸」变为「畸形输入」。

### 4.5 技能

- **形态**：一技能一目录，根含 `SKILL.md`（frontmatter：`name` / `description` / `version`）；
- **三级渐进披露**：L1 元数据（name/description）进 system prompt → L2 正文按需注入上下文 → L3 引用文件按需读取（**经内容读取接口，不经文件系统**）；
- **激活**：显式 `activate_skill(slug)` 工具（④ 现行 D75）——命中后写回 `activated_skills`，该技能的依赖工具变为可见（§4.3 门控）；
- **不投影、不 staging、无文件系统语义**：技能内容存 DB/MinIO，按需注入；
- **权限**：`skill_acl` 复用 ACL v2 resolver（④ D73）；
- **依赖**：三类依赖（tool / mcp / skill）与门控沿用 ④ D74/D76/D78。

### 4.6 审批闸（D91）

- **对象**：**外部 MCP 写工具**（MCP server 注册时标注读写语义）；本地只读知识工具不拦（延续 D30/D33）；
- **协议**：`ask_question` 单事件 —— `ask_id` / `tool_use_id`（与 tool_call 精确关联）/ `deadline` / `reason`（answered / timeout / canceled）/ `answers`；
- **超时**：默认 600s 可配；超时或 Run 取消 → 拒绝 + `resolved` 事件；
- **二次校验**：批准后执行前复查工具与权限是否仍有效（防「批准后被关掉 / 被撤权仍执行」）；
- **超时隔离**：审批等待使用**不带 per-tool 超时**的上下文；批准后**重开**工具执行超时窗口；
- **跨副本**：本地投递优先，跨实例走 **Redis pub/sub + ack**，并校验租户与属主。

### 4.7 事件与恢复（D89）

- **事件清单**（在 D25 七事件基础上扩展）：`step` / `meta` / `citation` / `delta` / `usage` / `done` / `error` + `tool_call` / `tool_result` / `approval_required|resolved` / `artifacts` / `steer` / `context_compacted`；
- **重放**：事件 append 进 Redis List（key 含 session+message，TTL 1h）；重连端点从 offset 0 全量重放，之后轮询增量；重放前按 `event_id` 合并未完成 delta 以避免万帧；
- **超 TTL**：只能靠 DB 已完成消息，**进行中的半截内容不可补齐**——这是有意的成本取舍。

## 6. 三家参照的借鉴表（合并版）

| 能力域     | Yuxi                                       | Mira                                          | WeKnora                                                | 本设计取谁                                          |
| ---------- | ------------------------------------------ | --------------------------------------------- | ------------------------------------------------------ | --------------------------------------------------- |
| 运行态     | 7 态 + ARQ + PG lease + **checkpointer**   | 快照内无 Run 状态机                           | **无跨轮状态，每轮从 DB 重建 + 压缩检查点**            | **Yuxi 的状态机 + WeKnora 的无 checkpointer**（D88） |
| 断线恢复   | seq + `Last-Event-ID`                      | 主对话无；子任务有重放                        | **无 seq，offset 全量重放 + 轮询**（Redis 1h）         | WeKnora（D89）                                      |
| 审批       | `interrupt_on={工具名}`                    | `ask_question` 单事件协议                     | 仅 MCP；fail-close；10min；**执行前二次校验**          | Mira 协议 + WeKnora 两条补充（D91）                 |
| 执行环境   | 远程 provisioner（不可搬）                 | bwrap/safebox，每会话一个，挂载集             | 四档后端 + 不降级 + 不 bind mount                      | **都不取**（D87，本期不引入沙盒）                   |
| 技能激活   | 差量复制投影                               | bind-mount 投影                               | **`read_file` 读 SKILL.md 即激活，无专用工具**         | ④ 现行 D75（**不投影 + `activate_skill`**，因无文件系统） |
| 工具门控   | **注册与可见性解耦**（不可省略）           | ToolPackage + MCP 聚合                        | **MCP 按需 discover + `tool_ref` 校验**                | Yuxi 门控 + WeKnora 校验（D90）                     |
| 失败护栏   | —                                          | —                                             | **五类护栏 + `stall≠total` + 截断调用不执行**          | WeKnora（§4.2）                                     |
| 上下文压缩 | 阈值策略                                   | summary 中间件                                | **切点保 tool 配对 + 路径继承 + 降级归档 + 检查点落库** | WeKnora（后续细化）                                 |
| 产物       | `present_artifacts` + preview              | `Artifact{permission,allowed_users}` + 版本表 | ArtifactCollector 扫 output + 版本历史                 | Mira 模型 + 服务端生成（D87）                       |
| 查询理解   | 无                                         | 无（`knowledge_qa` 是工具）                   | 单层 ReAct，无 grade/rewrite                           | **本项目自有（保持）**：plan/grade/rewrite + 图检索 + ACL 下推 |

**一句话**：**从 Yuxi 借代码与协议，从 Mira 借形态与协议，从 WeKnora 借失败经验与工程常量。**

## 7. 分期与验收

| 段  | 内容                                                                                     | 验收                                                                            |
| --- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| **1** | Run 运行时（8 态 + `agent` 队列 + FIFO + attempt + 租约）＋ 五类护栏 ＋ 取消合成落库（D92）  | 既有 `/agent` 非流式回归绿；卡死/空转/截断可复现地被终止；取消后可查到部分结果     |
| **2** | 工具注册表（③ 3.6）＋ **产物服务与能力服务化**（D87）＋ 审批闸（D91）                        | 产物可生成/登记/下载（带权限与版本）；渲染服务输入校验生效；MCP 写工具未审批不执行 |
| **3** | 技能体系（④ Phase 1–3）＋ MCP 客户端（④ Phase 4）＋ 事件重放（D89）＋ 压缩细化              | 工具可枚举可门控；MCP 工具按需可见；断线重连不丢帧                               |

**关键路径**：三段均**不依赖任何外部基础设施**（不引入沙盒服务）——第 1 段可立即开工，第 2 段只需复用已有的转换/导出链路。

## 10. 未决问题

1. **报告渲染落点**：新建独立服务，还是并入 `kb` 的转换容器？（影响部署与队列划分）
2. **图表渲染的实现**：模板化图表（受控 DSL）还是渲染库直出？前者可控、后者灵活。
3. **压缩细化参数**：切点保 tool 配对、保留窗口比例、**路径继承需改写为本项目的「文档/片段号继承」**（WeKnora 继承的是文件路径，我们继承的是引用）。
4. **审批超时取值**：600s（WeKnora）还是 300s（Mira）——取决于交互形态（同步页面 vs 异步通知）。
5. **沙盒的触发条件与回归成本**（沿用 D86）：若出现「客户要装自己的脚本技能」「报告要跑代码」「要通用文件工作台」三者之一，需重新评估；届时**技能落地形态必须一并改**（内容注入 → 写文件投影），这是本期留下的已知架构债。
