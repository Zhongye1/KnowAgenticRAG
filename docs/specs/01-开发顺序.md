



    根据 [fastapi-best-practices](https://github.com/zhanymkanov/fastapi-best-practices) 等业界最佳实践  以及 [Python 项目工程化开发指南](https://pyloong.github.io/pythonic-project-guidelines/practices/web/) ，FastAPI 项目的推荐开发顺序遵循**"基础设施 → 安全 → 业务 → 入口"**的依赖链，具体如下：


## 推荐开发顺序（8 个阶段）

```
第1步: 配置管理 (Config)
    ↓
第2步: 数据库层 (Database + Models + Migration)
    ↓
第3步: 认证授权 (Auth / Security)
    ↓
第4步: 消息队列 (Message Queue / Celery) — 如需要
    ↓
第5步: 业务逻辑层 (Services)
    ↓
第6步: 路由层 (Routers)
    ↓
第7步: 中间件与异常处理 (Middleware + Exception Handlers)
    ↓
第8步: 测试与文档 (Tests + Docs)
```

---

## 第 1 步：配置管理（地基）

**为什么先做**：所有后续模块（数据库 URL、JWT 密钥、队列地址）都依赖配置。

```python
# core/config.py
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    DATABASE_URL: str = "postgresql+asyncpg://user:pass@localhost/db"
    SECRET_KEY: str = "change-me"
    ALGORITHM: str = "HS256"
    ACCESS_TOKEN_EXPIRE_MINUTES: int = 30
    CELERY_BROKER_URL: str = "redis://localhost:6379/0"
    
    class Config:
        env_file = ".env"

settings = Settings()
```

## 第 2 步：数据库层（持久化基础）

**为什么先做**：业务逻辑和认证都依赖数据存储。

**包含内容**：
- 数据库连接引擎（`create_async_engine` + `async_sessionmaker`）
- ORM 模型（SQLAlchemy / SQLModel）
- Alembic 迁移脚本
- `get_db()` 依赖注入

```python
# core/database.py
from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession, async_sessionmaker
from core.config import settings

engine = create_async_engine(
    settings.DATABASE_URL, 
    pool_pre_ping=True,
    pool_size=10,
    max_overflow=20
)
async_session = async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)

async def get_db() -> AsyncSession:
    async with async_session() as session:
        yield session
```

**lifespan 管理数据库生命周期**（推荐方式）：

```python
# main.py
from contextlib import asynccontextmanager
from fastapi import FastAPI

@asynccontextmanager
async def lifespan(app: FastAPI):
    # startup: 创建连接池
    await database.connect()
    yield
    # shutdown: 清理资源
    await database.disconnect()

app = FastAPI(lifespan=lifespan)
```

## 第 3 步：认证授权（安全网关）

**为什么先做**：80% 的业务接口需要登录保护，先建好认证体系，后续业务路由可以直接使用 `Depends(get_current_user)`。

**包含内容**：
- 密码哈希（`passlib` / `bcrypt`）
- JWT 生成与校验
- `OAuth2PasswordBearer` 依赖
- `get_current_user` 依赖注入

```python
# auth/security.py
from fastapi.security import OAuth2PasswordBearer
from jose import jwt
from core.config import settings

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/auth/login")

async def get_current_user(token: str = Depends(oauth2_scheme)):
    payload = jwt.decode(token, settings.SECRET_KEY, algorithms=[settings.ALGORITHM])

```

## 第 4 步：消息队列基础设施（异步骨架）

**为什么此时做**：如果项目需要异步任务（发邮件、生成报表、图片处理），需要在业务逻辑开发前搭好 Celery + Redis 的基础设施。

```python
# core/celery_app.py
from celery import Celery
from core.config import settings

celery_app = Celery(
    "tasks",
    broker=settings.CELERY_BROKER_URL,
    backend=settings.CELERY_BROKER_URL,
    include=["tasks.email", "tasks.report"]
)
```

> 如果项目**不需要**异步任务（纯同步 CRUD），这一步可以跳过。

## 第 5 步：业务逻辑层（核心）

**为什么后做**：业务逻辑依赖数据库模型和认证体系已经就绪。

**开发顺序**：按业务模块逐个开发，每个模块内部遵循 `models → schemas → repositories → services`：

```
users/
  ├── models.py      # SQLAlchemy ORM
  ├── schemas.py     # Pydantic 请求/响应
  ├── repositories.py # 数据库操作封装
  └── services.py    # 业务逻辑
```

```python
# users/services.py
from users.repositories import UserRepository
from users.schemas import UserCreate, UserResponse

class UserService:
    def __init__(self, repo: UserRepository):
        self.repo = repo
    
    async def create_user(self, data: UserCreate) -> UserResponse:
        if await self.repo.get_by_email(data.email):
            raise ValueError("Email exists")
        return await self.repo.create(data)
```

## 第 6 步：路由层（API 入口）

**为什么最后做**：路由只是"接线员"，把 HTTP 请求转发给 Service。等 Service 稳定后再写路由，可以避免反复修改接口定义。

```python
# users/router.py
from fastapi import APIRouter, Depends
from users.schemas import UserCreate, UserResponse
from users.services import UserService
from auth.security import get_current_user

router = APIRouter(prefix="/users", tags=["users"])

@router.post("", response_model=UserResponse, status_code=201)
async def create_user(
    data: UserCreate,
    service: UserService = Depends(get_user_service)
):
    return await service.create_user(data)

@router.get("/me", response_model=UserResponse)
async def get_me(current_user=Depends(get_current_user)):
    return current_user
```

**在 `main.py` 中统一注册**：

```python
# main.py
from fastapi import FastAPI
from users.router import router as users_router
from orders.router import router as orders_router

app = FastAPI(lifespan=lifespan)
app.include_router(users_router)
app.include_router(orders_router)
```

## 第 7 步：中间件与异常处理（全局横切）

**为什么此时做**：等路由都写好了，才能知道需要捕获哪些异常、需要哪些全局处理（请求 ID、耗时统计、CORS）。

**包含内容**：
- 全局异常处理器（统一 JSON 错误格式）
- 请求追踪中间件（X-Request-ID）
- CORS / 日志中间件

```python
# core/exceptions.py
from fastapi import Request
from fastapi.responses import JSONResponse

@app.exception_handler(Exception)
async def global_exception_handler(request: Request, exc: Exception):
    return JSONResponse(
        status_code=500,
        content={"code": "INTERNAL_ERROR", "message": "Server error"}
    )
```

**中间件执行顺序注意**：

```python
# 注册顺序（越后注册越外层）
app.add_middleware(CORSMiddleware, ...)      # 最内层
app.add_middleware(ErrorTrackingMiddleware)  # 外层
```

## 第 8 步：测试与文档（收尾）

**测试分层**：

| 层级 | 内容 | 工具 |
|------|------|------|
| 单元测试 | Service 逻辑、依赖覆盖 | `pytest` + `dependency_overrides` |
| 集成测试 | 真实数据库、端到端 API | `TestClient` + `pytest-asyncio` |
| E2E 测试 | 完整用户流程 | `httpx` / Playwright |

```python
# tests/conftest.py
from fastapi.testclient import TestClient
from main import app

client = TestClient(app)

def test_create_user():
    response = client.post("/users", json={"email": "test@example.com", "password": "123456"})
    assert response.status_code == 201
```

## 总结：开发顺序 checklist

| 顺序 | 模块 | 核心产出 | 依赖前置 |
|------|------|----------|----------|
| 1 | **配置** | `Settings` 类、`.env` | 无 |
| 2 | **数据库** | `engine`、`models`、`get_db()`、Alembic | 配置 |
| 3 | **认证** | `get_current_user`、JWT 工具、密码哈希 | 数据库 |
| 4 | **消息队列** | `Celery` 实例、任务定义 | 配置 |
| 5 | **业务逻辑** | `Service` 类、`Repository` 类 | 数据库 + 认证 |
| 6 | **路由** | `APIRouter`、端点定义 | 业务逻辑 + 认证 |
| 7 | **中间件/异常** | 全局异常处理器、追踪中间件 | 路由 |
| 8 | **测试/文档** | `pytest` 用例、OpenAPI 文档 | 全部 |

**下层不依赖上层**。配置 → 数据库 → 认证 → 业务 → 路由，这个依赖方向是单向的，不会出现循环导入。如果项目不需要消息队列，直接从第 3 步跳到第 5 步即可。
